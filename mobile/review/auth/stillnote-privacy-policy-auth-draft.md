### 1. 서비스와 정보 처리

Stillnote는 기기나 브라우저에 메모를 작성·저장·검색·편집·삭제·백업·복원하는 서비스입니다. Android·iOS 메모는 앱 전용 저장소에, 웹 메모는 해당 브라우저의 로컬 저장소에 보관됩니다. 현재 이 버전은 메모를 운영자 서버나 Firebase에 자동 업로드하거나 기기 간 동기화하지 않습니다. **로그인하지 않아도 무료 로컬 메모 기능을 이용할 수 있습니다.**

사용자가 계정 기능을 선택하면 이메일 주소와 인증에 필요한 정보(비밀번호 등)가 Google Firebase Authentication으로 전송되어 계정 생성, 로그인, 비밀번호 재설정, 이메일 확인, 계정 관리를 처리합니다. Firebase는 사용자 식별자(UID), 인증 상태 및 세션 정보 등을 처리할 수 있습니다. 비밀번호를 운영자 문의 메일로 보내지 마세요. 이 앱은 비밀번호를 운영자 서버나 메모에 별도로 저장하도록 구현하지 않았지만, Firebase의 인증 처리 및 보관에는 Google의 운영 방식이 적용됩니다.

### 2. 기술 정보와 외부 서비스

Android·iOS·모바일웹은 같은 Firebase 프로젝트의 계정을 사용합니다. 메모 저장소는 각각 별개이며, 로그인 상태가 기기나 다른 웹 주소로 자동 전달되는 것은 아닙니다. Firebase SDK는 로그인 유지를 위해 인증 세션을 기기 또는 브라우저에 보관할 수 있습니다. 웹 인증 코드에는 Firebase Analytics를 초기화하는 기능을 추가하지 않았습니다.

Stillnote의 인증 기능에는 Google Firebase Authentication이 사용되며, Android 인증 SDK에는 reCAPTCHA 관련 구성요소가 포함됩니다. Firebase는 인증과 서비스 유지, 보안·남용 방지 등을 위해 IP 주소, SDK/플랫폼 사용자 에이전트, 앱 식별 정보 등을 처리합니다. Android의 reCAPTCHA 기능이 실제 실행되는 경우 Google의 해당 SDK 공개 범위에 따라 기기·상호작용·무결성 관련 정보가 처리될 수 있습니다.

로그인을 사용자가 선택한다는 사실이 인증 SDK의 기술 정보 처리가 모두 선택적이라는 뜻은 아닙니다. SDK의 처리 정보와 실행 조건은 공급자 공식 자료 및 실제 출시 빌드를 기준으로 별도 확인합니다.

서비스 제공자: Google (Firebase Authentication 및 관련 보안 기능). [공급자의 서비스 제공자/처리자 지위, 국외 처리·이전 국가 및 방식, 목적, 이전 정보, 보유 기간, 이용자 권리와 연락처를 실제 계약·설정·적용 법률에 맞춰 확정한 뒤 게시해야 함.]

검토 근거: Firebase 공식 자료(2026-11-01 확인)는 Authentication의 처리 위치를 미국으로 설명하고, 기록된 IP는 수 주간, 그 밖의 인증 정보는 사용자 삭제 개시 후 운영·백업 시스템에서 180일 이내 제거한다고 설명합니다. 이는 공급자 설명이며 Stillnote가 직접 측정한 파기 완료 시점은 아닙니다. 이 사실을 반영하되 국외 처리 고지·동의의 최종 문구는 실제 계약에 맞춰 확정해야 합니다.

공식 참고: https://firebase.google.com/support/privacy  
Android SDK 고지: https://firebase.google.com/docs/android/play-data-disclosure#authentication  
reCAPTCHA 고지: https://docs.cloud.google.com/recaptcha/docs/disclosure-requirements-android

### 3. 메모 백업·공유와 문의

사용자가 메모 복사, 공유 또는 파일 내보내기를 선택하면 클립보드·시스템 공유 기능·문서 선택기를 통해 선택한 앱 또는 저장 위치로 데이터가 전달될 수 있습니다. JSON 백업에는 메모 내용 전체가 포함될 수 있습니다. 선택한 외부 저장소 또는 공유 서비스에 있는 사본은 해당 서비스의 정책이 적용됩니다.

이메일로 문의하는 경우 사용자가 보내는 발신 이메일 주소, 문의 본문 및 첨부가 운영자의 메일함에 접수될 수 있습니다. 문의 대응과 필요한 후속 처리에 사용하며, [보관 기간과 삭제 절차 확정 필요]를 기준으로 관리합니다. 문의에 메모 또는 비밀번호를 첨부할 필요는 없습니다.

### 4. 보관 기간과 삭제

로컬 메모는 앱에서 메모를 삭제하거나 앱 데이터를 제거할 때, 웹에서는 메모 또는 해당 사이트의 브라우저 데이터를 삭제할 때 제거할 수 있습니다. 브라우저의 저장 공간 정리 등으로 데이터가 제거될 수도 있으므로 영구 보관을 보장하지 않습니다. 별도로 내보낸 백업, 다른 앱·클라우드 사본, 클립보드 내용은 계정이나 앱 데이터 삭제와 함께 자동으로 삭제되지 않습니다.

사용자는 앱의 **더보기 → 계정 → 계정 삭제** 메뉴에서 현재 비밀번호를 재확인하고 Firebase 계정 삭제를 요청할 수 있습니다. 이 기능은 Firebase 사용자 계정 삭제를 수행하지만 **기기에 저장한 메모나 별도 백업 파일을 자동 삭제하지 않습니다.** 로그아웃과 앱 삭제는 Firebase 계정 삭제와 다릅니다.

앱을 사용할 수 없는 경우 [계정 삭제 안내: 공개 승인 후 실제 URL 삽입]에서 웹 계정 페이지로 이동하여 로그인하고 현재 비밀번호로 재인증한 뒤 직접 삭제하도록 제공할 예정입니다. 해당 코드는 구현·로컬 검증됐지만 공개 웹 서비스로 배포하지 않았습니다. 웹에서 삭제해도 같은 Firebase 계정이 삭제되며 각 기기·브라우저의 메모는 유지됩니다.

비밀번호를 잊은 경우 등록 이메일로 재설정 메일을 요청할 수 있습니다. 등록 이메일에도 접근할 수 없는 경우 문의 주소로 도움을 요청할 수 있으나, 이메일 주소를 적어 보냈다는 이유만으로 계정을 삭제하지 않습니다. [대체 본인확인·처리기한·완료 안내·요청 기록 보존 기준을 정한 후 공개 안내 확정 필요.] 비밀번호·인증 토큰·메모·백업 파일을 문의에 보내지 마세요. Firebase 사용자 삭제 성공은 공급자 로그·백업까지 즉시 모두 제거됐다는 뜻이 아닙니다.

### 5. 정보 보호 및 선택권

기기 메모에는 운영체제의 앱별 저장소 접근 제한이 적용됩니다. 앱 자체의 메모 종단 간 암호화를 제공한다고 주장하지 않습니다. Firebase Authentication은 해당 공식 자료에 따라 전송 중 HTTPS 암호화를 사용하지만, 앱의 모든 가능한 외부 공유 경로가 같은 보호 수준을 가진다고 단정하지 않습니다.

사용자는 로그인 없이 메모 기능을 사용하거나 계정을 만들어 사용할 수 있고, 앱 내에서 메모 확인·수정·삭제·내보내기 및 Firebase 계정 삭제를 요청할 수 있습니다. 문의 정보와 개인정보 관련 열람·정정·삭제 문의는 dla3946gns@gmail.com으로 보내 주세요. [이용자 권리 행사·불만 처리 및 국내법상 필수 고지 확인 필요].
