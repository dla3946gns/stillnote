# StillNote Play 데이터 보안 응답 초안

2026-10-31 / 미제출. 대상: Firebase SDK 연결 개발 버전, PR #25.

## 결론과 사용 방법

현재 상태에서 ‘데이터 수집 없음’으로 제출하는 것은 권고하지 않는다. SDK 기본 처리 여부가 남아 있어 최상위 수집 질문의 최종 답은 보류한다. 아래는 콘솔에 자동 입력할 확정 응답이 아닌 검토용 답안표다. 로그인 도입 후 항목은 별도로 표시한다.

## 질문별 응답안

| 질문 | SDK 연결 현재 버전 | 이메일 로그인 도입 후 제안 | 확정 조건 |
|---|---|---|---|
| 앱이 데이터를 수집하거나 공유하나요? | **보류:** SDK 자동 처리 확인 후 결정. 기존 ‘아니요’ 답안 재사용 금지 | **예:** 인증 정보 처리 포함 | 최종 AAB·SDK·실제 처리 경로 대조 |
| 어떤 계정 생성 방식을 제공하나요? | 앱 내 계정 생성 없음. 콘솔 제공업체 활성화만으로 계정 생성 UI가 생기지는 않음 | 이메일+비밀번호에 대응하는 콘솔 선택지 | 회원가입 실제 구현 후 확정 |
| 수집 데이터가 전송 중 암호화되나요? | **보류** | **보류:** Firebase만 보고 앱의 모든 경로를 ‘예’로 확정하지 않음 | 전체 전송 경로 확인 |
| 사용자 데이터 삭제 요청이 가능한가요? | 온라인 계정은 미제공. 기존 로컬 삭제·문의 처리를 질문별 구분 | 앱 내 계정 삭제 및 외부 요청 경로가 동작해야 답변 | 요청 처리 절차·실제 삭제·보관 예외 검증 |
| 독립적 보안 검토를 받았나요? | 앱 자체에 대한 검토 증빙 없음. 해당 질문이 있으면 ‘예’ 주장 금지 | 동일 | 공급자 인증을 앱 인증으로 대체하지 않음 |

## 유형별 검토 답안

| 데이터 유형 후보 | 수집·공유 응답 초안 | 목적·선택 여부 초안 | 미확인 또는 제외 근거 |
|---|---|---|---|
| 이메일 주소 | 현재 앱 입력 없음. 로그인 도입 후 ‘수집’ | 앱 기능·계정 관리, 선택적 로그인에서만 처리되면 선택 수집 후보 | 기본 SDK 처리의 선택 여부까지 확장 금지 |
| 사용자 ID | Firebase UID를 실제 발급·처리하는 로그인 버전에서 ‘수집’ | 계정 관리·앱 기능 | 앱 ID·패키지 이름은 사용자 UID와 다름 |
| 비밀번호·인증 토큰 | 전송 정보 목록에는 포함. 별도 Play 유형은 콘솔의 최신 정의와 실제 사용에 맞춰 결정 | 인증·세션 유지 | 임의로 ‘금융 정보’ 등 잘못된 유형에 배정하지 않음 |
| IP·SDK/플랫폼 정보 | SDK 공식 처리 항목. 실제 전송·사용자 연계에 따라 유형 확정 보류 | 서비스 제공·보안 등 실제 목적 대조 | IP가 있다는 이유만으로 위치 수집을 단정하지 않음. 위치를 추론하면 대략적 위치 검토 |
| 기기 또는 기타 ID | reCAPTCHA 사용 시 식별자 처리 여부 확인 후 결정 | 남용 방지 여부 확인 | Firebase Android 앱 ID만으로 기기 ID 수집이라 판정하지 않음 |
| 앱 상호작용·설치 앱·기기 무결성 | reCAPTCHA 버전·실행 조건별 확인 후 결정 | 보안·사기 방지 후보 | 최신 공급자 공개 목록 전체를 현재 APK의 실측 결과로 취급하지 않음 |
| 기타 사용자 생성 콘텐츠: 메모 | 기기 내 처리만 있는 메모를 수집 대상으로 추가하지 않음 | 로컬 메모 기능 | SDK 포함만으로 메모 전송을 가정하지 않음. 공유/백업은 사용자 요청 예외 검토 |
| 문의 메일 | 앱 밖의 자발적 이메일 문의와 앱 자체 수집을 구분 | 개발자 연락·지원 | 앱에 문의 폼·자동 로그 전송을 추가하면 재검토 |

공통 규칙: Google 전송을 곧바로 모두 ‘공유’ 또는 모두 ‘공유 아님’으로 표시하지 않는다. 개발자를 대신하는 서비스 제공자 예외 적용은 실제 계약·처리에 따라 판단한다. ‘일시적 처리’는 IP 등의 보관을 확인하지 않은 상태에서 선택하지 않는다. 기본 자동 처리에는 필수/선택을 별도 판정한다. [Play 공식 기준](https://support.google.com/googleplay/android-developer/answer/10787469)

## 계정 삭제 질문과 URL

로그인과 회원가입을 도입한다면 앱 내 삭제 경로와 앱 밖에서 계정·연관 데이터 삭제를 요청할 수 있는 웹 경로를 준비한다. 정책 URL이 있다는 사실만으로 삭제 요청 URL 요건을 충족했다고 답하지 않는다. 실제 공개 URL과 본인 확인·처리 절차가 없으므로 주소는 미기입 상태로 둔다. [Play 계정 삭제 요건](https://support.google.com/googleplay/android-developer/answer/13327111)

## 제출 전 남은 검증

1. 신규 설치·첫 실행·로그인 없이 사용 시 SDK 통신과 데이터 확인.
2. 로그인 구현 후 인증·삭제 각 경로 확인.
3. reCAPTCHA 18.6.1과 최신 공급자 공개 내용의 적용 차이 확인.
4. 최종 AAB와 실제 배포된 모든 대상 버전·지역의 데이터 범위 확인.
5. 개인정보처리방침과 이 답안을 일치시키고 운영자가 최종 승인.
