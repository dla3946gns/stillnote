# Stillnote Android 후속 업데이트 — Google Play 데이터 보안 신고 작성 초안

2026-11-01 / **미제출·미승인·콘솔 미입력**. 현재 심사 중인 Android 0.1.0은 변경하지 않는다.
대상: PR #25의 Android 이메일/비밀번호 인증이 최종 AAB에 포함될 후속 릴리스.

## 초안의 핵심 판정

- 최상위 '앱이 사용자 데이터를 수집 또는 공유하나요?': **수집 = 예(후속 인증 빌드의 응답 후보)**. 이메일 인증 정보와 Firebase 사용자 ID 처리로 기존 0.1.0의 '수집 없음' 답변을 그대로 쓰지 않음.
- '공유': Google이 서비스 제공자로서 처리하는 정보의 예외 충족 여부를 실제 계약·처리 목적에 따라 확인하고 별도 응답. Firebase로 전송한다고 자동으로 전부 '공유'라고 하거나 전부 '공유 아님'이라 단정하지 않음.
- 계정 만들기 방법: **이메일과 비밀번호**(코드상 회원가입 가능). 다른 로그인 제공업체를 사용한다고 신고하지 않음.
- 앱 내 삭제: 더보기 → 계정 → 계정 삭제 → 현재 비밀번호 재인증 → Firebase 계정 삭제 요청. 실제 테스트 계정 삭제 성공 경로 검증 필요.
- 앱 밖 삭제: **웹 삭제 코드 구현·로컬 실계정 검증 완료, 공개 URL 미게시.** 웹에서 로그인·현재 비밀번호 재인증 후 직접 Firebase 사용자를 삭제한다. 공개 승인·HTTPS 배포와 등록 이메일 접근 불가 지원 절차가 남아 있다. Console에 임시 URL을 제출하지 않음. 정책 페이지를 사용할 경우에도 삭제 경로를 눈에 띄게 표시하고 실제 요청이 가능해야 한다.
- 전송 중 암호화: Firebase Auth 공식 안내는 수집 정보 전송에 HTTPS를 사용한다고 설명. 앱의 다른 모든 외부 공유 경로까지 검토한 후 최상위 질문에 최종 답변.
- 데이터 삭제 요청: Firebase 사용자 계정 삭제·웹 요청·계정 연관 데이터 처리 범위 확인 후 응답; 현재 모든 계정 데이터 삭제 지원을 확정하지 않음.
- 외부 독립 보안 검토: 앱 자체의 독립 검토 증빙 없음. Firebase 공급자의 인증을 앱 자체 인증으로 주장하지 않음.

웹 검증 근거와 네이티브 검증은 구분한다. 사용자가 테스트 계정의 비밀번호 변경·재인증 삭제를 진행했고 Console 사용자 삭제 상태를 확인했다. Android Auth 에뮬레이터와 iOS 시뮬레이터 빌드는 통과했으나 네이티브 실기기 동일 UID 검증은 사용자 결정으로 보류했다. 이는 초안 정리를 막지 않으며 출시 검증 완료를 뜻하지 않는다.

## 유형별 입력 가이드 (실제 Play Console 화면과 최종 SDK를 기준으로 확정)

| 데이터 유형 후보 | 현재 초안 분류·목적 | 선택/필수 및 연계 | 미확정 조건 |
|---|---|---|---|
| 개인정보 > 이메일 주소 | **수집 예 후보.** 회원가입·로그인·비밀번호 재설정·계정 관리 | 이메일 계정 기능은 사용자가 선택. 계정 생성 시 필수 | SDK가 자동 처리하는 다른 항목까지 선택 수집으로 표시하지 않음 |
| 개인정보 > 사용자 ID | **수집 예 후보.** Firebase UID, 계정·세션 식별 | Firebase 사용자 계정에 연결됨. 로그인 기능 사용과 연계 | 앱 식별자·설치 식별자와 Firebase UID를 구분 |
| 기타 개인정보·인증에 필요한 정보 | 비밀번호·인증 상태·세션 토큰 등 실제 인증 요청에 필요한 처리 | 로그인/재인증 때 사용 | Play 최신 분류에 맞춰 종류와 보관/사용 목적을 확인; 임의로 금융정보에 넣지 않음 |
| 기기 또는 기타 ID | reCAPTCHA가 실행되는 경우 기기 ID, 무결성·식별자 처리 여부 조사 | 보안/부정 사용 방지 후보 | 공급자 자료에 있는 모든 항목이 모든 기기에서 항상 처리된다고 단정 금지 |
| 앱 활동 > 앱 상호작용 등 | reCAPTCHA 요청에 해당 항목이 포함되면 신고 후보 | 보안/부정 사용 방지 후보 | 실제 요청 발생 여부, 설치 앱 처리 유형을 최종 확인 |
| 대략적인 위치 | IP를 사용하여 위치를 추론하는 처리 발생 시 검토 | 서비스 제공·보안 등 | IP 주소 수집만으로 '위치 수집' 자동 확정 금지 |
| 앱 정보·성능 및 기술 메타데이터 | Firebase user agent, Auth user agent, 앱 ID | 서비스 유지·보안·오류 대응 | Play 각 데이터 유형 해당 여부와 연결/일시적 처리 판단 필요 |
| 기타 사용자 생성 콘텐츠 (메모) | **자동 수집으로 단정하지 않음.** 로컬 저장·검색·편집 | 기기 내 처리 | 사용자가 명시한 공유·백업 전송과 SDK 자동 업로드 혼동 금지 |
| 운영자 이메일 문의 | 사용자의 앱 외부 자발적 문의 시 발신 주소·첨부 수신 | 고객지원 | 앱 내 자동 수집과 구분; 앱 내 문의 폼 추가 시 재검토 |

## 분류 시 주의

1. '수집'은 기기 밖으로 전송되어 개발자 또는 SDK 제공자가 액세스할 수 있는 데이터를 기준으로 판단한다. SDK 기본 처리, 인증 사용 시 처리, 선택한 외부 앱으로 공유한 경우를 구분한다.
2. '필수/선택'은 **데이터 유형별**로 판단한다. 로그인 화면이 선택 사항이라는 이유로 Firebase Auth 기술 정보 전부를 선택 수집으로 표시하지 않는다.
3. '공유'의 서비스 제공자 예외, 일시적 처리, 연계 여부, 전송 중 암호화는 Google Play의 최신 정의와 Firebase 실제 운영을 대조한 뒤 결정한다.
4. 권한 선언(INTERNET, ACCESS_NETWORK_STATE, READ_GSERVICES)은 개인정보 종류·실제 데이터 전송 사실을 증명하지 않는다.
5. Firebase Authentication의 Android 고지는 user agent·IP·Android App ID의 기본 처리를 설명한다. reCAPTCHA 고지는 **SDK 요청을 받는 경우** IP, SDK 버전, 패키지명, 사용자 동작, 무결성, 앱 상호작용, 일부 설치 앱, 기기 식별자 등을 설명한다.
6. 비밀번호 등 비밀정보를 사용자 화면/로그/테스트 리포트에 노출하지 말 것.

## 콘솔 신고 전 필수 확인

- [ ] 심사 중 0.1.0의 실제 Play Console 신고 상태·AAB와 이번 초안을 구분.
- [ ] 후속 버전 최종 AAB의 모든 SDK·전이 의존성, 보안 설정과 인증 데이터 처리 검증.
- [ ] Play에서 실제 노출되는 데이터 유형·목적·연계·선택 여부·공유 예외를 공급자 계약/실제 사용과 대조.
- [ ] 로그인·삭제 실기기 시나리오 및 reCAPTCHA 실제 실행 조건 확인.
- [ ] 외부 **계정 삭제 요청 웹페이지**를 게시하고, 안전한 본인 확인, 실제 처리 절차·보관 예외 검증.
- [ ] 개인정보처리방침 웹·앱 내 본문과 데이터 보안 신고의 설명 일치. 운영자 최종 승인.
- [ ] 그 후에만 Play Console 데이터 보안 신고 수정·제출. PR CI 사전 검사 통과를 데이터 보안 신고 완료로 해석하지 않음.
