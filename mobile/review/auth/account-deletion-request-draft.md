# Stillnote 계정 삭제 — Android/iOS 사용자 안내 및 웹 요청 경로 준비

2026-11-01 / **검토용·미승인·미게시**. PR #25의 네이티브 인증과 PR #26의 모바일웹 코드를 기준으로 작성. 외부 삭제 페이지는 구현됐으나 공개 배포하지 않았고, 이메일 접근 불가 지원 절차는 미확정이다.

## 현재 앱 코드로 확인한 기능

- Android: 더보기 → 계정 → 계정 삭제. 현재 비밀번호로 Firebase Auth 재인증하고 같은 UID인지 확인한 뒤 Firebase 사용자 삭제.
- iOS: 더보기 → 계정 → 계정 삭제. 동일한 현재 비밀번호 재인증 및 Firebase 계정 삭제.
- 삭제 성공 후 UI는 '계정을 삭제했어요. 기기의 메모는 그대로예요.' 메시지를 표시.
- 계정 삭제는 로컬 메모와 기기 외부의 별도 백업/공유 사본을 제거하지 않음.
- Firebase 계정 삭제와 운영자 문의 정보 및 향후 구매·Plus 데이터 삭제는 별개. 현재 PR에는 구매/Cloudflare 연동이 없지만 도입하면 별도 삭제 절차를 구현해야 함.
- Android 로컬 Auth 에뮬레이터 계정 삭제 테스트는 존재. 실제 Firebase 서비스에서의 두 플랫폼 삭제·사후 데이터를 추가 검증해야 함.
- 웹: docs/delete-account/index.html → docs/account/?mode=delete → 이메일 로그인 → 현재 비밀번호 재인증 → 같은 UID 확인 → Firebase 사용자 삭제. dist/account에도 동일한 계정 코드가 있음.
- 웹 실제 테스트 계정 가입·로그인·로그아웃·확인/재설정 메일 수신을 관찰했다. 사용자가 비밀번호 변경·새 비밀번호 로그인·재인증 삭제를 수행했고, 이후 Console의 사용자 목록이 비어 있음을 확인했다. 공개 HTTPS 호스트에서의 검증, 네이티브 실기기 동일 UID 로그인 및 실제 웹 메모의 바이트 보존 검증으로 확대 해석하지 않음.

## 웹 리소스 게시안 (구현 완료·공개 URL 미확정)

페이지 제목: 'Stillnote 계정 및 관련 데이터 삭제 요청'

- 운영 주체: Anna Johnny Works. 문의: dla3946gns@gmail.com.
- 대상: Stillnote Android·iOS·모바일웹 사용자가 생성한 Firebase 이메일 계정. Google·Apple 계정 자체를 삭제하지 않음.
- 앱 이용 가능: 각 앱의 더보기 → 계정 → 계정 삭제 메뉴에서 본인 확인 후 직접 삭제.
- 앱 이용 불가: 웹에서 로그인한 뒤 현재 비밀번호로 다시 본인 확인하여 직접 삭제. 앱 재설치를 요구하지 않음. 비밀번호를 잊었지만 등록 이메일에 접근할 수 있다면 재설정 메일로 복구한 뒤 삭제.
- 절대 요청하지 않을 정보: 비밀번호, 인증 토큰, 전체 메모 또는 백업 파일.
- 본인 확인: 이메일 발신자 이름/주소만으로 소유권을 확정하지 않음. 등록 이메일 소유를 확인할 수 있는 안전한 일회성 검증 수단 또는 별도 인증 절차가 필요.
- 처리: 확인된 본인 요청을 실제 Firebase 계정 삭제로 연계, 처리 상태 및 완료/실패를 알릴 방법, 처리기한, 정당한 보관 예외를 운영자 정책으로 확정.
- 삭제 범위: 현재 구현은 Firebase Authentication 사용자 계정 삭제. 메모는 UID와 연결하여 서버에 저장하지 않으며, 로컬 메모·외부 백업은 유지됨. 사용자에게 메모 또는 앱/사이트 데이터를 직접 제거하는 방법을 안내. 존재하지 않는 Plus 서버 데이터까지 삭제한다고 약속하지 않음.
- 향후 Plus 권한 저장소가 연결되면 UID 기준 구매/이용권 기록을 누가/언제 삭제할지, 법률상 보관이나 부정 이용 방지 예외가 있는지 별도 설계.

### 공개 전 사용자 안내 문안

> Stillnote 계정을 삭제하려면 계정 페이지에서 로그인한 뒤 현재 비밀번호로 본인 확인하고 ‘계정 영구 삭제’를 선택해 주세요. 삭제 후 되돌릴 수 없습니다. 같은 Firebase 계정이 삭제되며 기기·브라우저의 메모와 별도 백업은 남습니다. 메모도 지우려면 각 앱·브라우저에서 별도로 삭제해 주세요. 로그아웃이나 앱 제거만으로 계정이 삭제되지는 않습니다.
>
> 비밀번호를 잊으셨다면 등록 이메일로 재설정 메일을 요청해 주세요. 등록 이메일을 사용할 수 없다면 지원 문의를 이용해 주세요. 비밀번호·인증 토큰·메모·백업은 보내지 마세요. 대체 본인확인과 처리 기간은 운영 절차 확정 후 안내합니다.

위 문안은 공개 페이지에 아직 반영하지 않았다. 지원 절차 미확정 문구를 그대로 운영 약속으로 게시하지 않는다.

### 이메일 접근 불가 시 운영 절차 초안 (미운영)

1. 문의는 가입 이메일과 문제 설명 등 필요한 최소 정보만 접수한다. 신분증·비밀번호·토큰·메모를 기본 증빙으로 요구하지 않는다.
2. 발신 주소나 계정 이메일 기재만으로 소유권을 인정하지 않는다. 검증 가능한 대체 소유권 증빙 기준을 운영자가 승인하기 전에는 수동 삭제를 수행하지 않는다.
3. 승인된 본인확인 후에만 최소 권한으로 대상 계정을 확인하고 삭제한다. 이번 작업에서는 관리 계정·Admin SDK·자동 삭제 서버를 만들지 않는다.
4. 접수·추가 확인·완료/불가 안내와 기록 파기 방법을 정한다. 회신/처리 기한, 보존 기간, 책임자 및 예외 사유는 미확정이며 임의의 기간을 약속하지 않는다.

## 스토어 정책 대응

- Google Play: 계정 생성 가능 앱에 대해 **앱 내 삭제 경로** 및 **앱 외부에서 삭제 요청할 수 있는 웹 리소스**를 준비하고 Play Console의 계정 삭제 URL 필드에 실제 URL 입력이 필요. 단순 개인정보처리방침 페이지 링크는 대체가 아님.
- Apple: 계정 생성 앱은 앱에서 계정 삭제를 시작할 수 있어야 하고, 비규제 일반 앱에 불필요한 전화/지원 이메일 전용 절차만 강제해서는 안 됨. 실제 사용자 삭제 경로·재인증을 검증해야 함.
- 지금은 웹 URL을 임의로 만들거나 '이미 운영 중'이라 주장하지 않음. 현재 공개 정책/Play 0.1.0은 변경하지 않음.
