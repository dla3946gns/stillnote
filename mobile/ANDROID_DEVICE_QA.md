# Stillnote Android 실기기 QA

> 이 문서는 **실제 Android 휴대전화에서 사람이 확인할 항목**입니다. GitHub Actions의 가상 기기 자동 테스트만으로 실기기 검증이 완료되었다고 판단하지 마세요.
> iOS 빌드·출시 작업은 진행하지 않습니다.

## QA용 APK 준비

1. GitHub 저장소의 **Actions**에서 QA PR의 최신 **Mobile PR validation** 실행을 엽니다.
2. 실행이 성공했다면 아래 **Artifacts**에서 `stillnote-android-debug-apk`를 내려받고 ZIP을 풉니다.
3. 추출한 `androidApp-debug.apk`를 Android 기기에 전송해 설치합니다. 이 파일은 **디버그 서명**, 개발·QA 전용이며 Play Store 배포용이 아닙니다.
4. Android의 APK 직접 설치 경고를 확인하고 본인 저장소에서 받은 파일인지 점검합니다.

**중요: 이미 Stillnote가 설치되어 있다면 앱을 삭제하지 마세요.** GitHub Actions가 만든 디버그 APK는 기존 설치 앱과 서명이 다를 수 있어 업데이트 설치에 실패할 수 있습니다. 앱을 삭제하면 기기 전용 저장소의 메모가 함께 삭제됩니다. **기존 메모를 JSON으로 안전하게 백업하기 전에는 삭제·데이터 초기화·강제 재설치를 하지 마세요.** 가능한 경우 별도의 테스트 기기를 사용하세요.

## 실제 기기에서 확인할 항목

테스트는 개인 메모 대신 새로 만든 **가짜 QA 메모**로 진행합니다. 실제 개인 메모, 파일 경로 및 백업 내용은 공개 GitHub 이슈에 첨부하지 마세요.

- [ ] **첫 실행:** 메모가 없는 상태에서 앱이 정상 실행되고 `새 메모`를 누를 수 있다.
- [ ] **저장:** 제목 `QA 한글 🌱`, 본문 `첫 줄\n둘째 줄 😀`을 입력해 저장하면 목록에 나타난다.
- [ ] **재시작:** 앱을 완전히 종료했다 다시 열면 제목·줄바꿈·이모지가 유지된다.
- [ ] **취소:** 저장된 메모를 수정하다 `취소`하면 기존 내용이 그대로 남는다.
- [ ] **미저장 경고:** 새 메모 작성 중 `목록`을 누르면 `저장` / `버리기` / `계속 편집`을 선택할 수 있다.
- [ ] **검색·고정·삭제:** 제목/본문 검색, 메모 고정 필터, 삭제 확인 및 `삭제 취소`가 작동한다.
- [ ] **백업 파일 만들기:** 목록 화면 `더보기 → 전체 메모 백업`에서 Android 문서 선택기가 열리고 저장 위치를 선택할 수 있다.
- [ ] **백업 파일 확인:** 선택 위치에 `memo-backup-날짜.json` 파일이 생기며 한글·이모지가 깨지지 않는다. JSON 배열에 `id`, `title`, `body`, `createdAt`, `updatedAt` 필드가 있다.
- [ ] **백업 복원:** 위에서 만든 **QA 메모만** 삭제한 후 `더보기 → 백업 가져오기`에서 JSON 파일을 선택하고 확인하면 메모가 복원된다. 그 사이 작성한 다른 메모는 유지된다.
- [ ] **중복 가져오기:** 같은 백업을 다시 가져와도 같은 ID 메모가 중복 생성되거나 기존에 수정한 메모가 덮어써지지 않는다.
- [ ] **파일 선택 취소:** 내보내기 또는 가져오기 중 Android 문서 선택기에서 취소하면 메모가 변경되지 않는다.
- [ ] **잘못된 백업:** 잘못된 JSON 파일을 가져오면 오류 안내가 표시되고 기존 메모가 보존된다.
- [ ] **텍스트 파일 내보내기:** 메모 메뉴에서 `텍스트 파일 저장`을 사용하면 제목·본문이 UTF-8 텍스트로 저장된다.
- [ ] **다크 모드:** Android 설정에서 다크 모드를 전환한 뒤에도 목록과 편집 화면이 읽기 쉽고 버튼이 정상 작동한다.
- [ ] **화면 전환:** 기기를 가로로 돌리거나 앱을 다른 앱 뒤로 보냈다가 돌아와도 저장된 메모가 유지된다.
- [ ] **파일 공급자 호환:** 기기에 Google Drive 또는 다른 문서 공급자가 설치되어 있다면 해당 위치로 백업 저장·복원도 확인한다(선택).

## 문제가 생기면

GitHub PR에 **기기/OS 버전, 작업 순서, 기대 결과, 실제 결과**를 남겨 주세요. 개인 메모가 보이는 화면이나 실제 백업 파일을 공개로 올리지 마세요. 먼저 테스트용 데이터로 문제를 재현한 뒤 공유하는 것이 안전합니다.

## 자동화된 검증과 남은 범위

GitHub Actions는 공통 로직 14개, Android 저장소 호스트 테스트 3개, Android 에뮬레이터 Compose UI 7개를 라이트·다크 모드에서 각각 실행합니다. 추가로 Android Downloads 문서 공급자의 `ContentResolver`로 JSON을 쓰고 읽는 계측 테스트 5개를 라이트·다크 모드에서 수행합니다.

**자동 계측 테스트는 Android 시스템 문서 선택기 화면 자체를 실제로 눌러 확인하는 테스트는 아닙니다.** 문서 선택기와 제조사별 저장소 공급자, 물리 기기의 키보드/회전/접근성은 이 체크리스트로 별도 확인해야 합니다.
